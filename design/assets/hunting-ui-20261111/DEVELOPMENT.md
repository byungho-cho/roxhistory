# 개발 지시문: 사냥 준비 → 전투 UI 적용

## 목표와 범위

최신 Figma 준비/전투/종료 확인 화면과 이 폴더의 독립 에셋을 기존 Godot 사냥 흐름에 연결합니다. 기존 저장·퀘스트·보상·진입 경로를 보존하고 별도 개발 브랜치에서 구현하세요. 이번 에셋 인계 브랜치는 실제 기능을 구현하거나 main에 병합하지 않았습니다.

먼저 저장소 `AGENTS.md`와 현재 개발 브랜치를 확인하세요. main 기준 커밋은 `57cdef0994ad2a4e597651b17ecbcccd99db052e`입니다. `codex/final-intro-hunt-formation`의 `cb74af74ad4bcd98eb98072798b3b3e73f50858b`에는 main보다 새로운 편성 그리드·초상·VS 접근 흐름이 있습니다. 이 작업을 과거 오른쪽 패널 UI로 되돌리지 마세요. 해당 개발 작업이 이미 통합됐는지 먼저 확인하고 필요한 변경만 적용합니다.

주요 진입점은 `game/scripts/main.gd`의 `HUNT_SCREEN`, `open_hunt`, `close_hunt`, 화면은 `deer_hunt_screen.gd`, 판정은 `deer_hunt_rules.gd`, 실제 인물·동물은 기존 `hybrid_character.gd`, `world_animal.gd`입니다. 전체 화면을 새 게임으로 재작성하지 않습니다.

## 1. 에셋과 좌표

- `manifest.json`의 신규 에셋과 `reused` 경로를 사용합니다. 배경/초상/GLB를 복제하지 말고 기존 경로를 연결하세요. 신규 PNG/SVG는 필요한 파일만 게임 자산 경로에 한 번 배치하고 자산 manifest를 갱신합니다.
- Figma는 1920×1080, 기존 화면 코드는 960×540 좌표를 사용합니다. 한 가지 디자인 좌표계에서 일관되게 변환하고 화면 비율·safe area를 분리합니다. 픽셀 값을 절반으로 옮긴 뒤 개별 요소를 다시 임의 확대하지 않습니다.
- HUD는 카메라 줌/이동과 분리합니다. 배경·인물·동물은 전장, 상단 UI·스킬·종료 확인은 고정 UI입니다.
- 3D 모델 크기는 준비/전투 사이에 갑자기 커지지 않도록 실제 모델의 화면상 높이와 발 위치를 비교합니다. 정지 원화는 크기·구도 참고이며 동작 가능한 새 캐릭터 파일이 아닙니다.
- UI 수치·이름·레벨·인원은 Label, 체력 채움은 독립 마스크로 구현합니다. Figma HP 예시 숫자를 밸런스로 고정하지 마세요.

## 2. 준비 화면

`layout/preparation-layout.json`과 준비 Figma `2265:75`를 기준으로 동일 숲 배경, 좌측 3인 편성, 아군 파랑 3×3 / 적 코랄 3×3 격자, 하단 사냥 준비·가방, 빠른 출전·전투 시작을 연결합니다. 기존 편성 교체·배치 흐름은 유지합니다.

- 최신 버튼: 빠른 출전 320×110 (1050,925), 전투 시작 480×135 (1400,905). 고정 코너/그림자 여백을 보존합니다.
- AUTO/X2는 최신 아이콘+라벨형 96×96입니다. 옛 텍스트 버튼·숨김 보존 인스턴스를 다시 띄우지 않습니다.
- 빠른 출전·가방은 기존 정의된 행동에 연결합니다. 새 재화 소모나 보상을 임의로 추가하지 않습니다.

## 3. 전투 진입·카메라

전투 시작 후 약 2~3초 동안 캐릭터와 사슴이 서로 접근합니다. 카메라는 전장 중앙을 부드럽게 따라가며 준비 화면의 실제 시점보다 약 10~20도 내려 얼굴이 더 보이는 사선뷰로 연결합니다. ‘90도에서 80도’는 예시였으므로 절대 각도로 고정하지 않습니다. 접근 후 사용자의 줌인/줌아웃을 허용합니다.

강타 시 해당 캐릭터, 협동 시 참가자 중심으로 카메라를 살짝 부드럽게 확대하는 방향입니다. 과장된 확대·흔들림을 피하세요. 카메라 보간/줌 값은 플레이 확인 전 임의 확정하지 않습니다. 정지 배경 판과 실제 3D 카메라의 시차·가림을 별도로 검증하세요.

## 4. 전투 버튼·충전·상태

- 타격: 큰 녹색 창 버튼. 절제된 평상 광채, 가볍고 빠른 평타 궤적.
- 강타: 아래쪽 작은 주황 돌망치 버튼. 구슬 1개 비용, 묵직한 한 번의 집중 충격.
- 협동: 위쪽 더 큰 빨강 3인 찌르기 버튼. 구슬 2개 비용, 여러 공격이 겹쳐 지속되는 묵직한 에너지.
- 버튼은 `배경 → 효과 → 아이콘` 독립 레이어. 아이콘은 원형 내부에 유지합니다. 비용 구슬은 버튼과 함께 이동/비례합니다.
- 현재 전투 크기: 타격 300, 강타 136, 협동 170px. 강타·협동과 타격의 시각 외곽 간격은 약 4px입니다. 정확한 좌표는 battle-layout을 사용합니다.
- 충전 구슬 3개는 타격 오른쪽 반원에 있습니다. 각각49.4px, 사이 약4px, 버튼 쪽으로 추가3px 이동한 최신 좌표를 사용합니다.
- 시간에 따라 구슬이 하나씩 차며 켜집니다. 강타1/협동2 소비를 사용합니다. 옛 UI의 숫자0.1/1/2를 다시 표시하지 않습니다. 타격에는 비용 구슬을 표시하지 않습니다.
- 기존 규칙의 gauge100·비용10/50/100·초당14 등은 이전 모델입니다. 새 3구슬 모델과 무비판적으로 혼용하지 말고 변환/밸런스는 확인 후 적용하세요. 충전 시간·타격의 자원 처리 세부 수치는 미정입니다.
- 강타·협동은 짧은 입력 피드백 후 사용 시 약1초 재사용 잠금. 타격은 이 잠금에서 제외합니다. 잠금의 공유/개별 범위와 효과 지속 시간은 구현 중 확인할 항목입니다.
- 비활성에서는 금색 원형 테두리를 유지하고 내부 배경·아이콘만 흑백, 입력 효과는 숨깁니다. 청옥 구슬은 활성 파랑 / 비활성 흑백이며 테두리는 유지합니다.
- 구슬 한 칸 완충 시 짧은 반짝임+띵, 강타·협동이 비활성→활성으로 바뀌는 순간 짧은 빛+띵. 동시/연속 이벤트의 소리를 합치거나 제한해 과다 재생을 막고 앱 음소거를 존중합니다. 효과음 파일은 이번 묶음에 없습니다.

## 5. 판정·자동·2배속

피해 적용과 승패 판정은 즉시 처리합니다. HP 표시만 짧고 부드럽게 감소시킵니다. 표시 보간 때문에 이미 죽은 대상에게 추가 공격하거나 종료를 늦추지 마세요.

이번 개발에서는 AUTO/X2를 실제로 연결합니다. 아래는 사용자 요청 1차 가안이며 정지 Figma에서는 미구현입니다.

1. AUTO를 켜면 다음 강타(1구슬) 또는 협동(2구슬)을 무작위로 하나 미리 예약합니다.
2. 예약한 스킬의 필요량이 찰 때까지 기다립니다. 대기 중 매 프레임 재추첨하거나 협동을 강타로 바꾸지 않습니다.
3. 유효 대상·비용·재사용 잠금·전투 상태를 모두 만족할 때 한 번 실행하고 비용을 한 번만 차감합니다.
4. 실행 후 다음 무작위 예약을 만듭니다. AUTO 해제·전투 종료 시 예약과 대기 콜백을 정리합니다.
5. 타격/수동 스킬과 AUTO가 동시에 들어오는 경합을 막고 무효 입력은 비용을 쓰지 않도록 합니다. 수동 입력 후 예약 유지 정책은 확인하세요.
6. 2배속은 전투 시간에 적용합니다. 전역 엔진 속도를 무조건 바꿔 UI·음향·저장까지 빨라지게 하지 마세요. 접근, 공격, 충전, 잠금, HP 보간 중 어떤 항목이 전투 시간에 속하는지 명시하고 판정·소모·보상이 1배속과 일관적인지 검증합니다.

## 6. 종료 확인

뒤로가기는 즉시 나가지 않고 60% 검정 딤 위에 중앙 종료 확인 팝업을 띄웁니다. 질문은 ‘전투를 종료할까요?’, 왼쪽 메탈 ‘종료’, 오른쪽 금색 ‘계속’입니다. 팝업 뒤에는 별도 오래된 스크린샷 대신 **현재 전투 장면**을 그대로 유지합니다.

미정인 팝업 중 전투 정지 여부, 종료 후 복귀 화면, 보상·소모 처리 정책을 먼저 확인합니다. 기존 보상/소모를 임의로 재정의하지 않습니다. 중복 팝업·연타·뒤로가기·취소·종료 경합을 처리하세요.

## 7. 완료 조건

- 정지 화면을 준비/전투 Figma와 실제 실행 캡처로 비교: UI 위치·크기·텍스트·사슴 얼굴 크롭·모델 크기·아이콘 마스크·금색 비활성 테두리.
- 1배/2배, AUTO 켜기/끄기, 구슬0/1/2/3, 강타/협동/타격 연타, 비용 부족, 대상 사망, 마지막 타격과 승패, 종료 중 스킬, 다시 진입, 앱 중단/복귀를 테스트.
- 구슬 비용·예약·잠금·즉시 판정과 HP 보간에 전용 자동 테스트 추가. 현재 저장소에서 사냥 전용 suite는 확인되지 않았습니다.
- 자산 검증과 `scripts/check-village.sh`의 적용 가능한 검사를 수행. 기존 회귀 실패와 새 실패를 분리하고 실행하지 않은 검사도 명시합니다.
- Android의 실제 터치 영역, safe area, 성능, 카메라 가림, 음소거를 확인합니다. headless 통과만으로 시각/기기 검증 완료라고 하지 않습니다.
- 최종 변경·검증·미결 항목을 보고합니다. 승인 없이 main 병합·배포·버전 변경·릴리스 생성은 하지 않습니다.
