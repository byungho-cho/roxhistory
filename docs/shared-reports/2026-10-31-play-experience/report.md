## 기준과 보존

## 검증에서 발견한 문제와 조치

- PC 합성 입력에서는 핀치가 통과했지만 Android 대칭 핀치에서는 화면이 확대되지 않았다. Godot 4.5.1 Android 경로가 기본 스크롤 임계값에서 대칭 이동을 전달하지 않는 현상을 확인했다. `disable_scroll_deadzone`을 켜고 원시 터치 소유권을 유지하며 Android에서 다시 검증해 확대를 확인했다. [엔진 입력 구현](https://github.com/godotengine/godot/blob/4.5.1-stable/platform/android/java/lib/src/org/godotengine/godot/input/GodotGestureHandler.kt)
- 불러온 JSON의 숫자가 `0.0`으로 보이는 HUD 표시를 정수 형식으로 수정했다. 실제 재고는 변경하지 않는다.
- 목표 배지가 확대된 캐릭터 머리와 겹치는 장면을 발견해 근접 대상 배지를 숨겼다.
- 초기 목표 구역 테두리가 배경에 묻혀 어두운 외곽선과 연두/금색 선을 함께 사용했다.

## 자산과 편집 원본

- 주인공: 기존 자체 제작 절차형 3D 모델·15본 리그를 수정. `game/scripts/hybrid_character.gd`, `character_geometry.gd`, `hero_motion.gd`. 외부 모델/애니메이션 다운로드 없음. 프로젝트의 기존 캐릭터와 사용자 제공 Figma 시안을 참고했다.
- 초상화: 같은 3D 모델을 Godot에서 직접 렌더. 원본 재생성은 `game/tests/play_capture.gd`, 결과 `game/assets/ui/hero_portrait.png`.
- 목재·돌·임무·움집 아이콘: 기존 Figma 에셋 재사용. 씨앗 아이콘: 이번 작업에서 작성한 편집 가능한 `game/assets/ui/seed.svg`.
- 물소리: 외부 녹음 없는 원본 합성. `scripts/river_audio.py`와 `scripts/build_demo_audio.py`, PCM WAV/해시 목록. 다른 11개 음원 바이트는 유지했다.
- 배경·오브젝트·폰트는 기존 자산과 사용 조건을 유지했다. 새 유료 자산이나 불명확한 외부 사용권을 추가하지 않았다.

## 검증 구분과 남은 범위

PC: Windows, Godot 4.5.1, OpenGL Compatibility, RTX 5060. 합성 다중 터치 검사와 실제 렌더 관찰을 구분한다. Android: API35 / Android15 x86_64 읽기 전용 AVD, 1280×720. 일반 저장과 별도인 `--test-ui` 저장을 사용한다. 비교 화면 위치만 명시적으로 지정하며, 전체 플레이 검증은 별도로 실제 입력으로 수행한다.

실물 Android 기기, 폴더블 힌지/운영체제 전환, 실제 스피커·이어폰 청취, 장시간 발열·배터리는 미검증이다. 오디오 PCM 캡처와 음량/반복 경계 검사는 사람의 청취 평가를 대신하지 않는다. 배경은 기존 래스터이므로 최대 확대에서의 선명도 한계도 비교 화면으로 검토한다.

최종 검사·실행·PR·소스 기준·APK 링크와 증거 목록은 통합 검증 뒤 이 보고서에 갱신한다.

현재 로컬 회귀 검사: 937건 통과, 필수 이미지/벡터 27개 및 음원 12개 무결성 검사 통과. Android 실제 입력 전체 루프 27.52초, 취소 5항목, 다중 터치/복귀 8항목 통과. 최종 소스 기준 재빌드·화면 비율·소리 수명주기와 CI 결과는 후속 검증으로 갱신한다.

추가 접점 검증: 준비 이동은 실제 충돌 이동을 사용하고, 1.2초 작업 시계는 자세를 잡은 뒤 시작한다. 퀘스트 자원 8방향과 나머지 자원 좌우 등 26가지 접근에서 도구가 자원 그림 범위에 닿고 1개만 지급됨을 확인했다. 움집과 겹치는 자세는 대체 위치를 사용한다. 준비 이동 중 취소·중복 입력도 검사했다.

첫 원격 CI #25는 캐릭터 검사의 물리 프레임과 렌더 프레임 간 타이밍 차이로 취소 검사가 실패했다. 기존 조이스틱 검사처럼 고정 60Hz 엔진 시간으로 실행하도록 통일했다. 검사를 삭제하지 않았으며 준비 이동과 실제 작업 시간은 별도로 확인한다. 후속 CI 결과를 최종 보고에 기록한다.

성능 보완: 첫 비교에서 확대용 768×960 캐릭터 뷰포트를 항상 사용하면 기본 화면의 평균 처리 간격이 17.34ms에서 24.30ms로 늘었다. 기본 384×480, 1.5배 이상 확대 시 768×960으로 전환하고 1.25배 이하에서 되돌리는 방식으로 변경했다. 해상도 전환 첫 프레임의 캐릭터 표시·월드 크기·발 접점 유지 검사를 추가했다. 최종 Android 재측정은 전달 결과에 기록한다.
