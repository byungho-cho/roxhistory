# 건축 부지 선택·건설 연출·입력 구분 — 2단계

2026-11-04. 기준 HUD 커밋 `9f3e975`를 보존한 같은 작업 브랜치의 후속 구현이다. 이번 문서는 전체 라운드 완료/배포 보고가 아니다.

## 실제 반영

- 6개 후보 중 부지를 눌러 선택한다. 재료가 있으면 해당 입구까지 기존 경로 탐색으로 이동한 뒤 건설한다. 재료가 없으면 선택만 유지하고 부족한 재료를 안내한다.
- 이동 중 같은 부지를 다시 누르거나 ‘부지 선택 취소’를 누르면 경로와 선택을 취소한다. 다른 후보로 변경할 수 있다. 건설이 시작되면 부지는 고정되며 다른 작업 대상 클릭으로 바뀌지 않는다.
- 후보 위치는 `(1170,760)`, `(1510,830)`, `(1080,1150)`, `(500,640)`, `(350,1240)`, `(1780,1230)`. 건물 바닥 다각형·물 충돌·기존 오브젝트·그려진 바위 구역을 검사한다. 실제 경로와 도착도 각각 검사한다. 일시적으로 주민 등이 점유한 곳은 건설을 거절한다.
- 후보 표시는 원형 말뚝·밧줄·금빛 지면 테두리로 변경했다. [Figma 건설 원화](https://www.figma.com/design/zkbflw9fCdAlWbphhw5pSS?node-id=579-85)를 기준으로 기존 비계 PNG를 재사용하고 먼지·금빛 상승광·완료 파동을 연결했다. 표현 코드는 지급/저장을 변경하지 않는다.
- 새 저장에는 건설마다 `site`와 실제 지불한 `cost`를 기록한다. 기존 `homes` 배열에 부지 번호가 없으면 원래 순서별 `(1145,625)`, `(1390,810)`, `(1060,1030)`에 그대로 대응한다. 최초 단일 건물 저장도 기존 위치/외형/수령 여부를 유지한다.
- 건물 한도 3채, 나무1+돌1, 건설2초, 씨앗10개를 유지한다. 비용은 성공한 저장 때만 차감한다. 중복 부지 번호와 잘못된 저장값을 검증한다.
- 자원 재생성은 모든 후보 부지를 피한다. 동물은 넓은 원형 회피 대신 건물 바닥에 맞춘 타원 범위를 피하도록 조정해 기존 토끼 이동을 막지 않는다.

## 클릭의 의미

| 입력 | 진행 중 작업 |
|---|---|
| 자원·건물·후보 부지·작업 버튼 재클릭 | 유지, 재시작/중복 지급 없음 |
| 퀘스트/가방 상세 창 | 일시 정지, 닫으면 이어짐 |
| 카메라 드래그·핀치·Ctrl+휠 | 작업 유지, 자동 경로만 중단 |
| 이동 가능한 빈 땅의 짧은 탭 | 기존 탭 이동 명령으로 해석, 경로가 성공적으로 계산된 뒤 작업 취소 |
| 강·막힌 목적지·도달 불가능한 빈 땅 탭 | 안내만 표시, 진행 작업 유지 |
| 조이스틱/방향키 | 작업 및 자동 경로 취소, 직접 이동 |
| 명시적 일시정지/화면 전환/앱 중단 | 기존 안전 동작으로 취소, 미완료 작업은 비용/보상 반영 없음 |

‘배경 일반 클릭’과 이동 의도는 좌표만으로 별도 추측하지 않는다. 기존 빈 땅 탭 이동 기능을 유지하므로 **도달 가능한 빈 땅 탭은 이동 명령**이다. UI와 작업 대상은 여기에 포함되지 않는다.

## 검증 중 발견해 수정한 사항

- 초기 후보 하나가 토끼와, 다른 후보가 주민과 겹쳐 위치를 변경했다.
- 후보 회피 반경 확장으로 토끼가 움직이지 못하는 회귀를 발견하여 실제 부지 모양에 맞게 회피 범위를 줄였다.
- 화면 전환 직후 이전 경로 표시가 이미 해제된 월드에 접근하는 오류를 방어했다.
- 과거 고정 부지 좌표와 ‘퀘스트/핀치가 작업을 취소한다’는 검사는 현재 요구와 달라 계약을 갱신했다. 저장/지급, 실제 건설 완료, 보행 등의 검사는 유지한다.
- 별도 headless 에디터 준비에서는 설정 안전 저장 오류가 한 번 발생했다. 이를 성공한 빌드로 처리하지 않았다. 실행 스크립트의 실제 컴파일·렌더·검사 결과는 별도로 확인한다.

## 철거 정책/배포 최신 상태

최신 사용자 답변은 **자원별 실제 비용10개 이하=100%, 10개 초과=90%**다. 10개는 전액 반환한다. 롱프레스·간단한 확인창·주민 유지는 유지된다. 따라서 현재 나무1/돌1은 각각1개 반환하며, 이전0.9개 미정 때문에 현재 철거를 막을 이유는 해소됐다. 실제 철거 UI/거래 구현은 다음 단계다.

미사용 고비용에서는11개→9.9개,15개→13.5개가 된다. 자원별1/10 단위 잔여값을 저장해 다음 환급에 누적하고, 예상창에도 즉시 지급분과 잔여분을 함께 표시하는 방식을 제안한다. 아직 미확정된 큰 비용 정책을 현재1/1에 적용하지 않는다.

사용자 ‘APK는 따로 말이 없으면 항시 배포해줘’에 따라 **이번 라운드 검증 후 공개 APK 배포는 승인됨**. 이전 보고서의 배포 승인 대기는 이 지시로 대체한다. 현재 단계만 별도 중복 배포하지 않고 후속 시각/Android 작업과 통합한다.

남은 후속 범위: 배경 없는 프로필의 원형 프레임/원화 대조, 메뉴 돌받침, 식물·바위 가림·발접지와 충돌/경로, 첫 안내 정리, 지정 소리 아이콘 확대, 현재1/1 철거 구현과 미사용 고비용 소수 처리, Android/최종 회귀/통합 APK.
