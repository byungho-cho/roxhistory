# P4 UI·카메라·소리 개발 검토

2026-10-30. 기존 따뜻한 2D 강변 배경과 3D 캐릭터, 나무1·돌1의 짧은 흐름을 유지했다. 새 지역·퀘스트·전투·UI 전면 교체는 없다. 이번 단계의 구현·검증 완료와 실기기/최종 청감 승인·전체 베타 완료를 구분한다.

## UI

글꼴의 기본 굵기가100인 가변 Noto Sans KR에서 문자열 `wght` 설정이 적용되지 않아 텍스트가 가늘게 보였다. [Godot FontVariation 문서](https://docs.godotengine.org/en/stable/classes/class_fontvariation.html)의 숫자 OpenType 태그로600을 지정해 실제 굵기를 수정했다. 기존 글꼴·따뜻한 패널 색·아이콘을 재사용했다.

제목 뒤에 어두운 패널을 두고, 밝은 재료/목표 패널의 불투명도와 비활성 버튼 글자 대비를 높였다. 행동 안내와 저장 알림은 왼쪽 상단의 같은 영역을 번갈아 사용한다. 첫 구현의 하단 안내가 캐릭터 손·몸을 가리는 것을 실행 영상에서 발견하고 재배치했다. 작업 막대도 안내 아래로 옮겨 중앙의 채집·건설 장면을 확보했다. 재고 변경은 짧은 색 변화로 알린다.

## 소리

외부 녹음·모델·음악을 가져오지 않고 `scripts/build_demo_audio.py`에서 고정 시드로 합성한12개 WAV를 사용한다. 원본·길이·피크·RMS·SHA-256은 `game/assets/audio/manifest.json`에 기록했다. 역사적 악기 복원음이나 현장 녹음이라고 주장하지 않는다.

- 나무·돌·건설은 서로 다른 공명/짧은 잡음으로 구분하고 각2개 변형을 교대한다.
- P3의 도구 타격 이벤트에서 소리를 재생한다. 획득·완공·보상음은 GameState 저장 성공 이후에만 발생한다.
- 강물·바람은 별도2개 루프이며 강가에 가까울수록 물소리가 조금 커진다. 음악을 추가해 분위기를 바꾸지 않았다.
- 팝업에서 환경음8dB 감쇠, 화면 이동·백그라운드·음소거에서 정리. 복귀 때 루프2개만 다시 시작한다. 효과음 풀은6개로 제한한다.
- 음소거 설정은 기존 값을 유지한다. 왼쪽 뒤로가기 → 안내·소리 → 소리 켜기/끄기. 켜진 상태로 강제 변경하지 않는다.

[소리 포함 Android 실제 플레이](stage4/android-stage4-loop.mp4). scrcpy5.0.1의 Android playback capture로 게임의 출력음을 화면과 함께 녹음했다. 별도 효과음을 영상 위에 덧씌우지 않았다. [공식 녹화 설명](https://github.com/Genymobile/scrcpy/blob/v5.0.1/doc/recording.md).

## 카메라와 전환

현재 비스듬한 시점·줌·오프셋을 유지했다. 물리 프레임의 Camera2D 추적에 짧은 평활화를 적용하고 진입/화면 크기 변경 때 즉시 기준점을 맞춘다. 자동 줌·진동·카메라 흔들림은 추가하지 않았다. 이동 검사에서 추적 지연14.75월드 단위, 정지 후 목표2단위 이내로 수렴했다. 화면 전환은0.28초의 짧은 페이드이며 터치 입력을 가로채지 않는다.

## 검증과 구분

Windows/Godot4.5.1/RTX5060에서 기존649개와 새 P4 45개 =694개 통과. 에셋25개 무결성, 새 음원12개의 해시·PCM·음량·루프 경계 검증 통과. 2026-10-30 12:57–13:15 UTC에 로컬 검사와 실제 렌더를 검토했다. P3/P4 중간 상태 검사는 고정60fps 엔진 시간, Android는 실제 시간으로 별도 실행한다. 검사 삭제·조건 완화 없음.

Android15/API35 x86_64, 별도 AVD RoxHistoryP3, 호스트 RTX5060,1280×720. 실제 ADB 터치로 새 게임→각1회 채집→건설→보상10→강제 종료·이어하기·홈 복귀를 확인했다. [시간·상태 원시 기록](stage4/android-stage4-loop.json). 알려진 경로 재생 시간이며 처음 플레이한 사람의 시간과 다르다. 영상의 검은 재시작 화면과 홈 화면은 의도한 종료/복귀 검사다.

최종 게임 소스의 전체 터치 흐름30.75초(13:25:25 UTC), 오디오 출력/음소거 검사13:24:29 UTC, 작업 중 취소·복귀13:27:06 UTC 통과. Android 녹음 파일은 평균-39.5dBFS/최대-12.4dBFS로 클리핑 없이 출력됐다. 환경음 전경-44.93dBFS/복귀-45.37dBFS, 백그라운드·음소거·음소거 후 재시작은 PCM0이었다. 음량 측정은 소스/기기 설정/녹음 조건에 한정한다.

[오디오 출력 검사](stage4/android-audio.json): 전경/복귀에서 신호 존재, 백그라운드·음소거·음소거 상태 재시작에서 무음, 복귀 시 중첩 증가 없음. Android `output` 캡처의 remote-submix는 미디어 볼륨 경로에서 추가 감쇠가 있어 최종 녹화는 `playback` 소스를 사용했다. 측정 음량을 실제 기기의 음압이나 주관적 음질로 해석하지 않는다. PCM 파형·클리핑·루프 경계·발생 시점과 무음 구간을 검사했으며 사람의 최종 청감 승인을 대신하지 않는다.

커버/펼침/일반 가로 화면의 주요 패널·조작 버튼·보상 카드 경계와 실제 렌더를 검토했다. ADB 화면 크기 전환은 물리 폴딩 기기 검증이 아니다. 녹화·초기 진입 포함 Android 성능 로그도 남기며 항상60fps라고 주장하지 않는다.

최종 커밋 기준 원격 CI, APK v2/v3 서명·패키지·이전 공개 APK 업데이트 호환성, main 트리 일치와 실제 다운로드 해시는 PR/릴리스에 고정 SHA·시각으로 기록한다. 로컬 사전 빌드의 결과와 최종 전달 파일을 혼동하지 않는다.

## P5 후속

첫 사용자가 도움 없이 동선을 이해하는지 관찰, 실제 Android 폰·ARM GPU·스피커/이어폰·물리 폴딩·발열·장시간 확인. 음색 선호와 환경음/효과음 상대 크기는 사용자 피드백 대상이다. 새 캐릭터 아트의 세밀한 질감, 물리 그림자와 경사 지형은 기존 잔여 항목으로 유지한다.

## 원격 검사 시점 보정

첫 [CI 실행](https://github.com/byungho-cho/roxhistory/actions/runs/41064380080)에서 기존 hybrid_tests의 정지 후12물리 프레임 검사가 실패했다. 조이스틱은 `_process`에서 전달되므로 llvmpipe의 느린 렌더 프레임 사이에 여러 물리 틱이 진행되면 해제 입력 전달이 지연된다. 해당 합성 검사도 기존 P3/P4 검사와 같이 `--fixed-fps 60`으로 실행해 입력·물리 틱을 맞췄다. 30개 검사와 정지 기준 `<0.01`은 그대로이며 제품의 이동·애니메이션 코드는 변경하지 않았다. 실제 시간의 Android 터치 검사는 별도로 유지한다.
