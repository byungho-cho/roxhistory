# RoxHistory 품질 로드맵과 진행 현황 v0.1

기준일: 2026-10-30 KST. 단계 범위와 완료 기준은 최신 사용자 합의를 따릅니다.

## 목표와 현재 위치

**암사동 한 지역에서 1~2분만 플레이해도, 완성된 게임의 매력과 확장 가능성을 느끼는 데모**

지역 하나 · 첫 보금자리 퀘스트 하나 · 움집 하나. 세계·캐릭터·상호작용·연출·보상·저장이 연결된 경험.

현재 초점: **P1 완료 / P2 기본 동작 보완·Android 전체 루프 확인, 아트 품질 검토 중**

팀장 단계 검토 완료 1/5. 작업량 백분율은 산출하지 않는다. 사용자 피드백은 수시 반영하며, 단계마다 사용자 응답을 기다리는 승인 절차를 두지 않는다.

사용자가 다음 단계 판단을 팀장에게 위임했다. 범위 안의 구현·시각·동작·회귀 검증을 팀장이 확인하면 다음 단계로 진행한다. 큰 기획 변경·범위 확장·핵심 위험만 사용자와 별도로 조율한다.

단순 기능 데모를 넘어, 첫 진입부터 채집·건설·보상·저장·이어하기까지 연결되고 캐릭터·환경·소리·UI가 반응하는 소규모 테스트 빌드. 정식 베타 완료를 선언하는 것은 아니다.

기존 기준선: 사용자가 Android 데모의 기본 실행·화면 동작을 직접 확인했다고 보고함. PR #5 병합·CI 성공·에뮬레이터 기본 플레이 기록은 기술 기준선이며 전체 기기 QA 완료는 아님.

기존 기능 데모에는 시각·동작·환경 연출이 부족하다는 사용자 피드백. 본 로드맵의 품질 단계 완료와 별도 관리.

아트 기준: 아기자기한 2.5D, 둥근 형태, 따뜻한 자연광, 자연 재질, 갈색·금빛 UI

## 일정 운영

단계별 구현·검증·팀장 판단으로 순차 진행한다. 개발 담당의 작업 분해 후 목표일을 기록하고, 근거 없는 완료일은 약속하지 않는다. 사용자 피드백 대기를 일정의 필수 조건으로 두지 않는다.

1단계의 P1.1부터 시작하고, 각 품질 단계의 검증과 팀장 판단 후 다음 단계를 진행합니다. 사용자 피드백은 수시 반영합니다. 날짜가 정해지기 전에는 지연·정상 판정을 하지 않습니다.

## 단계별 범위와 완료 기준

### P1. 배경·오브젝트와 살아 있는 환경

체험 목표: **캐릭터를 세워두어도 강변 마을을 탐험하고 싶다.**

작업 범위:

- 강·강둑·흙길·풀밭을 하나의 작은 공간으로 연결
- 나무·풀·돌·움집·생활 소품·건설 터를 개별 오브젝트로 구성
- 시점·크기·바닥 접점·그림자·앞뒤 가림·충돌 정렬
- 강물 흐름과 잔물결, 풀·잎의 은은한 바람 움직임

| 작업 | 산출물 | 완료 확인 | 상태 |
| --- | --- | --- | --- |
| P1.1 에셋 구조와 아트 기준 | 기존 에셋의 재사용·분리·신규 제작 목록과 기준 구도 | 지형·물·식생·돌·건물·소품이 필요한 단위로 분리되고 시점·색감 기준이 일치 | 완료 |
| P1.2 지형과 오브젝트 배치 | 강변 정착지 한 구역의 정적 실행 장면 | 이동 동선 확보, 앞뒤 가림과 충돌 정렬, 기존 채집·건설 위치 유지 | 완료 |
| P1.3 물과 식생의 움직임 | 강물·잔물결과 풀·잎의 반복 환경 연출 | 반복 경계·깜박임·과도한 동기화 없음, 효과 전후 성능 비교 | 완료 |
| P1.4 검증·전달과 팀장 검토 | 같은 구도의 전후 캡처, 실제 영상, APK와 검증 기록 | 기존 기능 회귀·환경·이동 검토와 Android 기본 실행 기록 확인. 사용자 피드백은 후속 반영 | 완료 |

단계 완료 기준:

- 독립 오브젝트가 실제 장면에 배치되고 배경에 박힌 UI·인물과 중복되지 않음
- 강가와 건물 주변을 이동하며 가림·충돌이 보이는 위치와 일치
- 물·식생이 움직이고 반복이 눈에 띄지 않음
- 모바일 비율에서 주요 공간·UI 잘림 없음, 기존 기능 회귀 없음

전달물:

- 동일 구도의 적용 전후 캡처
- 물·식생·가림 관계를 보여주는 실제 실행 영상
- 확인 가능한 APK, 에셋 목록, 변경 커밋·PR, 성능 비교 기록

이번 단계 제외: 캐릭터 애니메이션, 전투·다른 지역, 새 퀘스트, 환경음·음악의 본격 제작

다음 행동: 잔여 시각 개선과 실기기 성능 검증은 후속 목록에 유지하고 P2로 진행

### P2. 캐릭터 이동·대기·행동 애니메이션

체험 목표: **걷고 멈추는 것만으로 캐릭터가 살아 있다고 느낀다.**

작업 범위:

- 우선 4방향 걷기·대기·채집 동작 준비
- 이동 속도와 발걸음·방향 전환·동작 전환 연결
- 발 접점·그림자·오브젝트 가림을 1단계 공간에 맞춤
- 플레이어 필수 동작 검증 후 필요시 간단한 주민 대기 반응 추가

단계 완료 기준:

- 방향과 이동 애니메이션이 일치하고 발 미끄러짐·뜬 느낌이 없음
- 정지·재이동·연속 방향 전환 시 튀거나 입력이 막히지 않음
- 채집 동작과 이동 중단·복귀가 안정적으로 이어짐
- 방향별 크기·시점·그림체가 일관됨

전달물:

- 방향·상태별 애니메이션 목록과 에셋
- 실제 이동·대기·채집 전환 영상
- APK와 입력·충돌 회귀 결과

이번 단계 제외: 8방향 확대, 전투 동작, 다수 주민 AI

다음 행동: P2 메시·도구 아트의 잔여 표현 검토. P3에서 자원 타격 반응·획득 효과·건설 단계 연출 준비

### P3. 채집·건설의 상호작용과 보상

체험 목표: **내 행동이 자원과 마을을 바꾸며 손맛과 성취감을 준다.**

작업 범위:

- 근접 대상 강조와 행동 가능·불가능 상태 안내
- 채집 동작·타격·자원 획득·수량 반영 연결
- 지정 터 건설 과정과 완성 변화 연출
- 짧은 주민 반응·퀘스트 완료·한 번만 지급되는 보상
- 데모는 나무·돌 각 1개로 건설, 채집 1.2초·건설 2초의 짧은 흐름 유지

단계 완료 기준:

- 접근·행동·결과·보상이 하나의 흐름으로 이해됨
- 동작·효과·자원 반영 타이밍이 맞음
- 자원 부족·중단·연속 입력·종료 복원에서 중복 지급 없음
- 건설 전후 공간 변화와 완료 상태가 명확함

전달물:

- 채집에서 움집 완성까지 실제 영상
- 상호작용 상태표·임시 밸런스 목록
- APK와 저장·중복 처리 검사 결과

이번 단계 제외: 자유 건설, 제작 트리, 복수 퀘스트·경제 시스템

다음 행동: P2 팀장 검토 후 행동 타이밍과 연출 설계

### P4. UI·소리·카메라와 장면 전환

체험 목표: **화면·소리·조작 반응이 하나의 게임으로 자연스럽게 이어진다.**

작업 범위:

- Figma의 패널·버튼·뒤로가기·텍스트 대비·안전 영역 정리
- 버튼·팝업·자원·퀘스트 변화의 짧은 반응 연출
- 강물·바람·행동 효과음과 절제된 배경음 연결
- 지역 진입·카메라 추적·전환과 설정·중단·복귀 처리

단계 완료 기준:

- 핵심 상태를 읽기 쉽고 터치·팝업 입력이 중복 전달되지 않음
- 소리와 행동·환경이 맞으며 앱 복귀 시 중첩 재생 없음
- 카메라·전환이 조작을 방해하거나 멀미를 유발할 정도로 흔들리지 않음
- 커버·펼침·일반 가로 비율에서 버튼·글자·안전 영역 확인

전달물:

- UI 상태·소리·카메라 연출 목록
- 소리가 포함된 실제 플레이 영상
- APK와 화면 비율·앱 복귀 검사 기록

이번 단계 제외: 새 테마·수익화·복잡한 설정 메뉴

다음 행동: P3 팀장 검토 후 UI·오디오·카메라 통합

### P5. 짧은 통합 데모와 시연 품질

체험 목표: **1~2분 안에 장소의 매력, 조작의 재미, 성장 가능성을 느낀다.**

작업 범위:

- 첫 진입·탐색·채집·건설·보상·다음 기대의 흐름 편집
- 첫 체험 안내와 목표·동선·데모용 수량을 실제 플레이로 조정
- Android 설치·터치·중단 복귀·저장·성능 검증
- 앱 버전·커밋·APK·시연 영상·검증 결과 일치 확인

단계 완료 기준:

- 도움 없이 첫 행동과 목표를 이해하는지 실제 관찰
- 장시간 반복 채집 대신 1~2분 내 핵심 경험 전달을 목표로 실측·조정
- 대표 Android 기기에서 전체 흐름·저장 복원·화면 비율 검증
- 치명적 진행 차단 없음, 미검증·임시 요소를 명시하고 사용자 최종 확인

전달물:

- 최종 APK와 다운로드 링크·해시·기준 커밋
- 조작부터 보상까지 편집으로 숨기지 않은 실제 시연 영상
- 기기·OS·조건·플레이 시간·성능·잔여 문제 보고서

이번 단계 제외: 정식 출시·스토어 심사 완료, 콘텐츠 대량 확장, 투자 유치 성과 보장

다음 행동: P4 팀장 검토 후 전체 시연 구간의 플레이 실측

## 진행 상태의 정의

| 상태 | 판정 기준 |
| --- | --- |
| 대기 | 선행 단계의 팀장 검토 또는 구현 준비를 기다림 |
| 착수 준비 | 범위와 완료 기준이 정해졌으며 구현 착수 전 |
| 진행 중 | 구현 활동 또는 변경 근거가 확인됨 |
| 검증 대기 | 구현됐지만 실행·시각·회귀 검증 전 |
| 사용자 검토 | 선택적 피드백을 받는 상태이며 다음 단계 진행을 자동 차단하지 않음 |
| 보완 중 | 발견 문제 또는 사용자 피드백을 수정하는 상태 |
| 완료 | 단계 범위의 필수 기준·근거·팀장 검토가 충족됨. 제품 전체 완료와 구분 |
| 막힘 | 작업을 진행할 수 없는 원인·다음 조치가 명시됨 |

## 검토와 현행화

1. 구현 및 근거 기록
2. 실행·시각·회귀 검증
3. 팀장 검토와 필요한 보완
4. 오류 없으면 main 병합 및 APK 단독 링크 전달
5. 다음 단계 진행, 사용자 피드백은 수시 반영

현행화 규칙:

- 개발 시작·구현 완료·검증 완료·막힘·사용자 확인 때 현황을 갱신
- 실행 중 표지만으로 진행 중 판정하지 않고 커밋·로그·실행 결과 확인
- 검사 통과와 시각·동작 품질을 별개로 평가
- 날짜는 KST 기준, 미정은 null로 보존하고 지연 여부는 합의 목표일이 있을 때만 판단
- APK·영상·검증에 기준 커밋·기기·OS·시각·미검증 범위 기록
- 품질 단계 완료는 범위 내 검증과 팀장 판단으로 인정하며 사용자 응답을 필수 조건으로 두지 않음
- 단계 범위·목표일 변경 시 이유와 이전 값을 이력에 남김
- 현황 JSON을 바꾼 뒤 Markdown·PDF·Figma 도식의 상태를 함께 갱신
- 현재 현황은 요청/개발 보고 시 갱신하는 기록이며 백그라운드 자동 감시가 아님
- 별도 요구가 없으면 작업 검증 후 오류가 없을 때 main에 병합
- 게임 변경 완료 시 ZIP 대신 서명된 APK 단일 파일 직접 다운로드 링크를 최종 보고에 제공
