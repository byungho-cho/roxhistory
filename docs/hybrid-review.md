# 2D 배경 + 실제 3D 캐릭터 비교 실험

이번 빌드는 제작 방식 결정을 위한 비교 실험이다. P2 아트 최종 승인·전체 3D 전환·베타 완료를 뜻하지 않는다.

## 인수 및 범위
main 307240c398fee2d98bb9d9b87b7518f42317e3d0(PR #8 병합)을 기준으로 별도 체크아웃에서 작업했다. 기존 저장소의 미반영 로드맵 문서는 변경하지 않았다. 배경·나무·움집·자원·2D 충돌·카메라와 이동/채집/건설/보상/저장 코드를 재사용했다.

플레이 화면 왼쪽 위 뒤로가기 → **2D로 비교 / 3D로 비교**로 전환한다. 선택은 기기에 저장하며 신규 설치의 기본은 3D다. 전환해도 위치·진행·이동 속도가 바뀌지 않는다. 데모 비용은 나무1+돌1, 각1회 채집, 채집1.2초·건설2초다.

## 실제 3D 구현과 출처
`game/scripts/hybrid_character.gd`가 구·원기둥 등 입체 메시를 생성하고 15개 관절의 Skeleton3D와 BoneAttachment3D로 연결한다. 평면 캐릭터 그림을 돌리는 방식이 아니다. 모델과 FK 관절 애니메이션은 이번 작업에서 프로젝트용으로 새로 작성했다. 외부 모델·모션·텍스처를 다운로드하거나 라이선스가 불명확한 자료를 가져오지 않았다. 기존 2D 그림·폰트는 기존 출처와 사용 조건을 유지한다.

큰 머리·둥근 팔다리·갈색 머리·황토색 의상·녹색 띠·돌도끼로 기존 정체성을 참고했다. 실제 이동 거리로 보행 위상을 계산하고 정지/재이동을 혼합한다. 아날로그 입력을 따라 중간 각도까지 회전하며, 호흡·고개·어깨/팔꿈치/몸통 채집 동작을 연결했다. 도구는 손 뼈의 자식이다.

256×320 투명 SubViewport에서 고정 사선 직교 카메라로 렌더한 뒤 기존 2D 장면에 합성한다. 3D 지면 원점의 투영을 발 기준점으로 사용한다. 기존 Y 정렬과 원형 충돌을 공유하고 2D 모드에서는 3D 뷰포트 갱신을 끈다. 키와 서명 파일은 저장소에 포함하지 않는다.

## 시각 검토
`hybrid/comparison.mp4`는 같은 위치·카메라·속도에서 2D 다음 3D의 대기·여러 방향 이동·정지·채집을 보여 준다. `compare-*-idle.png`와 `compare-*-gather.png`도 같은 조건이다. 나무/움집 앞뒤 캡처와 실제 물리 이동 검사로 가림을 확인했다.

3D의 중간 방향 회전과 관절 동작은 확인했다. 기존 그림과 크기·따뜻한 빛·발 기준을 맞췄으나, 새 모델은 단순한 장난감/점토 인상이며 기존 페인터리 그림의 재질 밀도에는 미치지 못한다. 어깨·팔꿈치·무릎은 분리된 둥근 메시 접합이며, 최종 제작용 스킨 메시가 아니다. 도끼 파지와 궤적은 검토했지만 모든 각도의 미세 관통이나 발 미끄러짐이 없다고 보증하지 않는다.

그림자는 기존 타원 그림자다. 배경의 실제 3D 광원/그림자와 상호작용하지 않는다. 전체 오브젝트 단위 Y 정렬이므로 가지 사이·복잡한 아치·높이 차 지형의 부분 가림에는 한계가 있다. 경사·계단용 발 IK는 없다. 배경 전체를 다시 만들지 않았다.

## 검증
Godot 4.5.1, Windows, RTX 5060, 1280×720 네이티브 실행. 기존 에셋25·상태345·화면/입력76·환경17·이동/가림13·캐릭터66 검사를 유지하고 실제3D30·3D가림13 검사를 추가했다. 실행 시각과 결과는 함께 저장한 JSON/로그를 기준으로 한다. 원격 CI와 최종 소스 커밋·APK 해시는 PR 및 Release에 기재한다.

Android 15 API35 x86_64 에뮬레이터, 호스트 RTX5060 GPU, 화면1280×720(게임 논리 뷰포트960×540), ADB 터치 입력으로 3D 새 게임→나무1회→돌1회→건설→보상10→종료/이어하기를 확인했다. 최초 전체 루프27.38초는 알고 있는 경로의 자동 터치 및 캡처 대기를 포함하며 신규 사용자의 플레이 시간은 아니다. 저장을 편집하거나 순간이동하지 않았다. 실제 Android 폰/ARM GPU·발열·배터리·장시간 플레이·물리 폴딩은 미검증이다.

## 같은 조건 성능 비교
|환경|2D|3D|해석|
|---|---:|---:|---|
|Windows VSync OFF, 10,000프레임×3, 평균 프레임 시간 중앙값|1.597ms|1.800ms|약0.203ms 증가, 실행 간 변동 있음|
|동일 조건 드로 콜|186|245|캐릭터 하나에서59 증가|
|Android 에뮬레이터, 정지600프레임 평균|16.859ms|16.751ms|둘 다 약60fps 제한, 3D가 더 빠르다는 의미 아님|
|동일 Android 측정 p95|31.594ms|30.924ms|호스트 스케줄링을 포함한 프레임 간격|

Android 측정은 전환 후 60프레임을 버렸고, Windows 측정은 1초 준비 후 10,000프레임을 기록했다. CPU/GPU 실행 시간 전용 프로파일러가 아닌 실제 프레임 간격이다. 실기기 성능이나 다수 주민 성능으로 일반화하지 않는다. 3D 모드에서도 기존 2D 메시 계산을 보존하고 있어 향후 최적화 여지가 있다.

## 다음 제작 작업과 선택 기준
|항목|혼합 방식 유지|전체 3D 확대|
|---|---|---|
|추가 캐릭터|공통 스킨 메시/리그, 의상·얼굴·모션 클립, UV/재질 제작|같은 캐릭터 작업에 전체 조명/스케일 규약 추가|
|배경|현재 그림 재사용, 접점·가림 마스크·그림자 개선|지형/건물/식생 모델·UV·재질·충돌·LOD 재제작|
|카메라|현재 고정 시점에 최적화|회전/높이 변화 가능하나 가려진 면과 카메라 충돌 필요|
|동작 품질|파지/발 IK, 스킨 가중치, 클립 전환, 그림체 셰이더 보완|동일 작업 + 지형 경사/높이 대응|
|모바일|캐릭터 뷰포트·메시 배칭·여러 캐릭터 비용 검증|환경 전체 드로 콜·그림자·오버드로·메모리 예산 검증|

이번 결과는 방향 판단 자료이며 전체 3D 전환을 결정하지 않는다. 사용자/팀장 비교 검토 후 2D 유지·혼합 보완·전체3D 중 후속 범위를 정한다.

추가 Android 결과: 동일 APK의 2D 모드에서도 전체 루프28.75초 및 저장/이어하기를 통과했다. 3D 채집 중 이동·임무 팝업·Android 뒤로가기·홈 전환은 채집을 취소하고, 복귀 후 한 번 채집이 정상 완료됐다. 상세 시각은 android-interruptions.json 참조. 반복 네이티브 검사에서 저장된 3D 설정이 기존 2D 검사에 영향을 주는 문제를 수정해 --test-ui의 시작 모드를 2D로 고정했다. 실제3D 검사는 명시적으로 3D로 전환한다.

검사 재현성: 데스크톱 창 포커스 변경은 테스트 실행을 임의로 중단시킬 수 있어 --test-ui에서는 OS FOCUS 알림만 격리했다. 명시적 PAUSED/RESUMED 검사는 유지하며 실제 게임 실행에는 적용하지 않는다. Android에서 홈/복귀 취소는 별도로 실제 입력으로 확인했다. 실패 검사를 삭제하거나 조건을 완화하지 않았다.

업데이트 검증: 공개 P2 v0.1.2-stage2 APK와 동일 인증서(cf65aeec…bb1695f)로 서명했다. 에뮬레이터에서 P2로 저장을 불러온 뒤 uninstall 없이 새 APK를 덮어쓰기 설치했고, 저장 파일 바이트 및 건설/보상10/재고가 보존됨을 확인했다(20:03 KST, upgrade.json). 공개 P1은 기존에 다른 키로 배포되어 이 호환성에 포함되지 않는다.
