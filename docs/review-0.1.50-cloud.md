## 구현된 내용

1. 본부 단계별 주민 움집 한도 1/2/3/3채, 신규 건설 최대 3채. 기존 4~5채 저장은 검증·표시·주민 수용 계산에서 그대로 보존합니다.
2. 움집 단계별 수용 1/2/3/5명. 주인공과 본부는 제외합니다. 현재 실제 주민은 기존 가족 합류 후 2명이며 추가 주민을 임의 생성하지 않습니다.
3. 본부 업그레이드의 초소 선행 조건을 제거했습니다. 다른 건물은 본부보다 높은 단계로 새로 업그레이드할 수 없습니다. 기존 저장의 완료 건물과 진행 중 공사는 취소하거나 낮추지 않습니다.
4. 초소 건설은 본부 4단계에서 열립니다. 화덕 2단계·신당 3단계 해금 규칙은 모델에 반영했지만 두 건물의 건설·효과·비용은 미정이므로 실제 건설 기능을 추가하지 않았습니다.
5. 기본 건설자 1명. 신규 건설과 업그레이드가 건설자를 공유합니다. 설정의 개발용 무제한 토글은 기본 꺼짐이며 앱 재실행 시 초기화됩니다.
6. 본부 단계별 합산 활성 자원 노드 5/10/10/20개. 저장된 난수 시드로 배치하고, 소진되면 5~10분 뒤 빈 공간에서 재생성합니다. 기존 노드의 소진·재생성 기록은 지우지 않습니다. 목재/석재의 확정 비율이 없어 두 종류가 모두 존재하도록 교차 선택하며 위치를 랜덤 배치했습니다.
7. 본부 단계별 경계 60/70/80/90%. 기존 코드의 90% 경계는 본부 4단계에서 그대로 유지합니다. 비율은 고정 최대축소 기준 가로·세로 길이에 각각 적용합니다. 본부 상승 시 짧은 경계 강조와 안내 문구가 표시됩니다.
8. 주민별 나무꾼·돌 채집꾼·쉬기 지정. 한 번 채집한 뒤 매번 본부로 돌아와 자원을 입고합니다. 운반 중 재료와 직업을 저장하며 재시작·직업 변경·쉬기·저장 실패·창고 상한에서 재료가 중복되거나 소실되지 않도록 처리했습니다. 속도·채집량·작업시간은 기존 데모 값을 사용했습니다. 오프라인 생산은 추가하지 않았습니다.
9. 상단 주민 수/수용량 버튼과 작업 지정 화면. 가로·세로·초광폭에서 수치상 배치와 버튼 입력을 검사했습니다. 실제 픽셀 품질 검사는 별도입니다.
10. 코너 구름을 실제 화면 모서리 기준으로 배치하고 축소 상태에서 약 20 UI px가 보이도록 보정했습니다. 확대 시 사라집니다.

## 의도적으로 적용하지 않은 내용

- 새 2D 캐릭터: Figma B안은 제작 방향 확정 컨셉 시트입니다. 개별 투명 이미지·방향·걷기 자산은 아직 없으므로 기존 게임 캐릭터를 유지했습니다.
- 건물 이동·자유 배치: Figma에서 보류/후속 확장으로 표시돼 있고 이동 범위·비용·입력·취소 규칙이 미정입니다.
- 직접 탐험으로 걷히는 안개: 해제 방식·범위·강도가 미정입니다. 현재 구현은 단계별 이동 경계이며 탐험 안개와 동일한 기능이 아닙니다.
- 화덕·신당·훈련소의 실제 게임 효과와 검토용 분리 원화: 확정 비용·기능·생산용 자산 검증을 기다립니다.
- 주민 최대 15명은 수용 한도입니다. 모집/등장 규칙이 없는 추가 주민을 만들어 주지 않습니다.

## 검증과 기존 CI 문제

- Godot 4.5.1에서 headless 실행과 실제 장면·물리·입력·저장 검사를 수행했습니다. 상세 결과는 `review-0.1.50-checks.json`을 봅니다.
- `scripts/check-village.sh`로 에셋·오디오·스크립트 import와 현재 12개 테스트 묶음(동시 작업은 3개 시드)을 다시 실행할 수 있습니다. `GODOT_BIN`을 실행 파일 경로로 지정합니다.
- 기존 [CI #91](https://github.com/byungho-cho/roxhistory/actions/runs/42181135417)의 실패 2개는 새 게임이 나무·돌 500개로 시작하는데 테스트가 빈 지갑을 가정해서 발생했습니다. 부족 재료 테스트가 재료를 명시적으로 0으로 설정하도록 고쳤습니다. 시작 자원을 낮추지 않았습니다.
- 다음 UI 검사에는 예전 회전 화살표·텍스트 자원 라벨·2배 줌 기대값도 남아 있었습니다. 현재 메뉴의 애니메이션 중 중복 입력 차단, ResourceIndicator, 설정된 최대 줌을 검사하도록 테스트를 갱신했습니다. 새 HQ 한도에 맞춰 다주택 시험은 본부 단계를 명시합니다.
- 모든 과거 테스트를 최신 규칙으로 이식한 것은 아닙니다. `legacy_scene_checks`는 구형 좌표/해금 기준을 포함하므로 별도 정리가 필요합니다.
- 두 주민 동시 나무 채집은 3개 고정 시드에서 주인공·야생동물 충돌을 켠 상태로 각 1회 본부 입고를 확인했습니다. PC headless 일부 프레임 간격은 약 75~111 ms까지 늘어났으므로 Android에서 두 주민 동시 동작의 프레임 시간을 별도 측정해야 합니다.
- 현재 클라우드는 가상 디스플레이용 로컬 소켓을 허용하지 않아 렌더링 스크린샷을 만들지 못했습니다. **픽셀 품질·Android 실기기 터치·성능·APK 설치·서명은 미검증입니다. 원격 CI 전체 성공을 의미하지 않습니다.**

## 롤백 주의

태그는 소스 복구 기준입니다. Android는 낮은 versionCode로 일반 업데이트할 수 없으므로 0.1.50 설치 후 롤백 APK가 필요하면 기존 태그 소스에 더 높은 versionCode를 부여하고 같은 키로 다시 빌드해야 합니다. 기존 앱 삭제는 저장을 잃을 수 있습니다. 새 진행 상태에는 이전 버전이 이해하지 못하는 진행 중 본부 업그레이드 등이 있을 수 있으므로 업데이트 전 저장 사본을 보존하고, 이전 코드와의 호환성을 확인한 뒤 복구합니다.
