# 팀장·개발 담당 역할 분담

사용자 지정일: **2026-11-02**.

| 담당 | 범위 |
| --- | --- |
| 팀장 — 현재 디자인·기획 대화 | 요구사항과 우선순위 정리, Figma 작업, 문서·결정 기록, 개발 담당에게 전달할 지시문 작성 |
| 개발 담당 — 별도 개발 대화 | 전달받은 범위의 게임 구현, 테스트, 빌드, 실행 검증과 결과 보고 |

다음 작업부터 팀장은 게임 개발을 자동으로 시작하지 않습니다. 정리와 Figma·문서 작업을 진행한 뒤, **사용자가 요청하면 개발 담당 지시문을 남깁니다**. 이 역할 규칙은 현재 팀장 대화에 적용되며, 개발 담당의 구현을 금지하는 규칙이 아닙니다.

개발 지시문에는 기준 화면·채택 에셋·변경 범위·완료 기준·기존 동작 유지 사항·검증 방법을 포함합니다. 음악과 효과음의 채택·백업·확인 대기 상태는 [오디오 카탈로그](../assets/audio/catalog.json)와 결정 기록을 따릅니다.

**2026-11-02 A303 오디오 개발 예외는 마무리됐습니다.** 현재 팀장 대화는 Figma·요구사항·문서만 담당합니다. 이후 v0.1.17~19 구현은 별도 개발 담당의 기록이며, 현행화한 문서에서 해당 결과를 확인·연결합니다.

현황 기준은 [현재 개발 현황](current-status.md)입니다. 외형 승인·Figma 등록·게임 구현·실행 검증·체감 승인을 각각 기록합니다.

## 번호로 전달하는 지시문

대표님이 검토한 지시문은 마이닷이 [번호별 개발 지시문](개발지시/README.md)에 기록합니다. 승인본의 버전·근거를 확인한 뒤 대표님이 개발 담당에게 `개발-00001 작업해줘`처럼 번호로 전달합니다. 번호 발행이나 문서 PR 병합만으로 개발을 시작하지 않습니다. 개발 담당은 해당 승인 범위만 작업별 브랜치·PR에서 구현하고 같은 번호로 검증 결과를 연결합니다. 지시문 변경·재승인·중복 번호 방지·공개 저장소 기록 원칙은 디렉토리의 사용법을 따릅니다.
