## 3. 다음 작업의 역할과 진행 방식

- **팀장 — 현재 대화:** 요구사항·우선순위 정리, Figma, 문서, 결정 기록을 담당합니다.
- **개발 담당:** 이후 게임 구현·검증·빌드를 담당합니다.
- 사용자가 수정사항을 보내면 이 대장에 누적합니다. 바로 게임 코드를 수정하거나 개발을 시작하지 않습니다.
- 사용자 요청 시 누적 내용을 한 번에 개발 담당 지시문으로 정리해 남깁니다. 자동으로 다른 대화에 전달하거나 개발 담당을 실행하지 않습니다.
- 채택 음악·소리의 실제 파일과 결정 이력을 Git에 보관하는 기존 기준은 유지합니다.

### 취합 원칙

1. 사용자가 보낸 순서와 원래 의도를 보존하고, 화면·레이아웃 / 아이콘·에셋 / 문구 / 사운드 / 모션·효과 / 기능·흐름별로 묶습니다.
2. 중복 내용은 연결해 합치고, 서로 충돌하는 요청은 확인 사항으로 남깁니다. 확인 전 임의 확정하지 않습니다.
3. 사용자가 확정한 내용, 검토 중인 안, 참고 의견을 구분합니다. 우선순위가 정해지지 않았으면 미정으로 둡니다.
4. 수정사항을 받을 때마다 전체 개발 지시문을 다시 만들지 않고 누적합니다. 사용자가 요청할 때 한 번에 정리합니다.
5. 개발 지시문에는 변경 범위, 기준 화면·에셋, 구체적인 전후 동작, 완료 기준과 검증 방법을 포함합니다.
