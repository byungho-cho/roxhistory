# P2 개발 지시: 캐릭터의 생명력과 조작감

기준일: 2026-10-30. 사용자는 다음 단계 판단을 팀장에게 위임했다. 단계마다 사용자 확인을 기다리지 않는다. 범위 내 구현·시각·회귀 검증을 마치면 다음 작업으로 진행하고 중간 피드백은 수시 반영한다.

## 목표와 기준선

기존 배경·오브젝트 작업은 PR #7로 main에 병합됐다. 최신 main과 진행 중인 캐릭터 작업을 대조하고, 중복 구현 없이 P2를 진행한다. P1의 환경·충돌·저장 복원과 기존 게임 기능을 보존한다.

목표는 **걷고 멈추고 채집하는 캐릭터만 보아도 살아 있는 게임으로 느껴지는 상태**다. 기존 아기자기한 2.5D 그림체와 캐릭터 정체성을 유지한다.

## 구현 순서

사용자 추가 요구(2026-10-30): 데모 진행 요구량을 최소화한다. 움집 비용은 나무 1개·돌 1개, 채집 1회당 1개로 설정해 종류별 한 번씩 채집하면 건설 가능해야 한다. 채집 1.2초·건설 2초의 짧은 동작으로 테스트 시간을 줄인다. 목표 패널·임무 안내·건설 확인·실제 차감은 같은 설정을 사용하며 저장·보상 1회 지급은 유지한다. 이는 데모용 임시 밸런스이며 정식 게임 요구량으로 확정하지 않는다.

1. 캐릭터 기준 정리: 기존 캐릭터·배경과 시점·비율·빛 방향을 맞추고 발 접점·그림자·화면에서의 식별 크기를 정리한다. 에셋과 상태 목록을 기록한다.
2. 4방향 걷기와 대기: 실제 프레임 또는 관절 애니메이션을 사용한다. 이미지의 상하 흔들기만으로 걷기를 대체하지 않는다. 속도와 발걸음을 맞추고 정지·재이동·방향 전환이 자연스럽게 이어져야 한다.
3. 채집 동작과 상태 전환: 접근→정지→행동→대기/이동 복귀를 기존 채집 시간과 연결한다. 빠른 입력·팝업·뒤로가기·앱 중단 후 상태가 고착되지 않아야 한다.
4. 월드 통합과 검증: 나무·움집 앞뒤 가림, 발 접점·그림자·충돌, 화면 비율과 모바일 입력을 확인한다. 플레이어 필수 동작이 갖춰진 뒤 여력이 있으면 간단한 주민 대기를 추가한다.

## 완료 기준

- 방향별 크기·얼굴·옷·장비·시점이 일관되고 프레임 사이 캐릭터가 흔들려 보이지 않는다.
- 걷기·대기·채집의 동작 차이가 분명하며 발 미끄러짐과 뜬 느낌이 줄어든다.
- 이동 속도·조이스틱 방향·동작 전환이 일치하고 연속 조작이 끊기지 않는다.
- 팝업과 앱 중단 시 이동·행동이 적절히 정지하고 복귀 후 정상 상태로 돌아온다.
- 기존 채집·건설·보상·저장·이어하기와 P1 환경 기능에 회귀가 없다.
- 방향별 동작과 전환을 담은 실제 실행 영상, 확인 가능한 Android 빌드, 검증 환경·결과를 전달한다. 자동 검사 통과와 시각·동작 검토를 구분한다.

## 범위와 진행

새 지역·전투·성장 시스템·UI 전면 개편은 추가하지 않는다. 채집 타격 효과와 건설 과정의 본격 연출은 P3에서, 전체 소리·카메라·UI 마감은 P4에서 연결한다.

검증과 팀장 검토를 통과하면 사용자 응답 대기 없이 P3의 작업 분해로 이어간다. 큰 기획 변경이나 범위 확장은 별도 조율한다. P5에서는 전체 루프를 직접 플레이할 수 있는 테스트 빌드로 통합하며, 1~2분의 시연 구간과 전체 플레이 흐름을 함께 검토한다.

진행 시 quality-progress.json의 실제 착수·상태·커밋·PR·영상·검증·막힘·다음 조치를 갱신한다. 아직 착수하지 않은 작업을 진행 중으로 표시하지 않는다.

작업 완료 후 관련 검사·빌드·변경 검토를 수행하고 오류가 없으면 main에 병합한다. 최종 반영 소스 기준의 서명된 APK **단일 파일 직접 다운로드 링크**를 마지막 보고에 버전·기준 커밋·검증 결과와 함께 제공한다. 테스트용 APK를 소스·로그와 묶은 ZIP으로 전달하지 않는다. 문서만 바뀐 경우에는 기존 APK를 새 빌드처럼 보고하지 않는다.
