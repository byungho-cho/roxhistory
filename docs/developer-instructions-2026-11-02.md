현재 대화의 팀장은 요구사항·Figma·문서를 담당합니다. 구현·테스트·빌드·배포 결과 제출은 개발 담당이 진행합니다.

## 2. REQ-001 채택 앱 아이콘 적용

**채택안은 v002의 1안 「시대의 개척자」입니다.** 큰 영웅 얼굴과 선사 움집·조선 궁궐·현대 도시가 함께 있는 이미지입니다. 최초 v001의 영웅 단독안이나 추가 4·5안과 혼동하지 않습니다.

| 항목 | 지정 원본 |
| --- | --- |
| Git 원본 | `design/app-icon/selected/roxhistory-app-icon-selected-v001.png` |
| 규격 | 1254 × 1254, RGB PNG |
| SHA-256 | `62eee2ff9c5fe4976a1fa12ca6059299248bc711d9799c97b31cad80e91d4e80` |
| 선택·적용 기준 | [selected/README.md](../design/app-icon/selected/README.md), [manifest.json](../design/app-icon/selected/manifest.json) |
| Figma | [I100 · 10 · 앱 아이콘 / 채택 1안](https://www.figma.com/design/zkbflw9fCdAlWbphhw5pSS/RoxHistory-V1.0?node-id=402-120) |
| Figma 원본 노드 | `402:127`, 256·128·64px 미리보기는 같은 섹션에 배치 |

Figma에는 채택 디자인을 반영했고, **실제 앱 아이콘 적용은 개발 담당 대기 상태**입니다. Git PNG를 실제 제작 원본으로 사용합니다. Figma 전체 보드의 스크린샷을 잘라 아이콘으로 사용하지 않습니다.

### 구현 지시

1. 기존 게임 아이콘 연결과 Android 내보내기 경로를 확인합니다. 이전 검토본의 `game/project.godot`는 `config/icon="res://assets/app-icon-hut.png"`를 사용했습니다. 실제 현재 소스와 내보내기 설정을 확인해 새 아이콘으로 연결합니다.
2. 채택 PNG를 보존하고 게임용 내보내기 파일은 구분해 관리합니다. 새로 그리거나 다른 시안으로 바꾸지 않습니다.
3. 큰 영웅 얼굴의 인상, 밝은 원색 만화풍 색채, 입체 명암, 움집·궁궐·현대 도시의 구성을 유지합니다. 작은 움집만 남는 기존 표현으로 돌아가지 않도록 합니다.
4. 원형·둥근 사각형 등 런처 마스크와 작은 크기에서 실제 결과를 확인합니다. 얼굴의 핵심 부위가 잘리지 않고 세 시대의 구성이 가능한 한 유지되도록 합니다. 별도 회색 여백이나 검은 테두리를 덧붙이지 않습니다. 마스크 대응을 위한 구도 수정이 필요하면 원본과 별도 검토본을 남겨 팀장에게 확인받습니다.
5. 프로젝트 설정만 바뀐 상태에서 끝내지 말고, 빌드한 APK 내부 리소스와 설치 후 홈 화면·앱 목록에서 새 아이콘이 표시되는지 확인합니다. 캐시 때문에 이전 아이콘이 보이는 경우도 구분합니다.

v001·v002·v003의 다른 시안, 프롬프트, 원본·해시 기록은 백업으로 보존합니다. 앱 이름 RoxHistory와 기존 패키지·업데이트 설치 경로를 유지합니다.

## 3. FOLLOW-001 연속 선택음 검사 확인

이전 검토본의 [GitHub Actions #47](https://github.com/byungho-cho/roxhistory/actions/runs/41356008927)에서 다음 검사 1건이 실패했습니다.

`Rapid region selection makes one soft cue, without duplicate UI cue`

당시 로컬 PC 808개와 Android 에뮬레이터 13개 검사는 통과했으나, 위 원격 실패는 해결 완료로 기록하지 않았습니다.

1. 현재 동일 문제가 남아 있는지 재현하고 로컬·원격의 차이를 확인합니다. 관련 경로는 `game/scripts/soundscape.gd`, `game/tests/a303_audio_tests.gd`와 지역 선택 입력 연결을 먼저 확인합니다.
2. 한 번의 유효 지역 선택에 지역 선택음과 일반 UI음이 중복 연결되는지, 연속 선택의 재생 제한과 검사 시점이 맞는지 확인합니다.
3. 실제 동작 문제면 중복 호출·과도한 겹침을 수정합니다. 검사 환경·시간 가정의 문제면 동작 의도를 보존하면서 검사 원인을 교정합니다. 통과를 위해 검사를 삭제하거나 무조건 성공하도록 바꾸지 않습니다.
4. 빠른 지역 전환 후에도 마지막 선택과 정보 패널이 일치하고, 선택음이 두 겹으로 울리거나 비정상적으로 커지지 않는지 실제 출력으로 확인합니다.
5. 원인, 변경 내용, 재현 방법, 수정 후 검사 결과를 기록합니다. 문제가 이미 해결된 상태라면 해결 커밋과 재검증 근거를 남깁니다.

## 5. 완료 기준과 검증

- [ ] 채택 PNG 해시가 지정 원본과 일치하고, 실제 설치 앱에서 1안이 표시됩니다.
- [ ] 원형·둥근 사각형 마스크와 작은 표시 크기의 결과를 화면으로 제출합니다. 기존 아이콘 대비 확인이 가능합니다.
- [ ] FOLLOW-001의 원인과 해결 또는 현재 해결 상태의 근거를 남깁니다. 관련 로컬·원격 검사가 통과합니다.
- [ ] A303 진입, 세 지역 선택, 빠른 연속 선택, 확대·복귀에서 선택 상태와 패널이 정상입니다.
- [ ] BGM·선택음·환경음을 함께 들어보고, 반복 경계를 지나도 재생 중단·크래시·이중 재생이 없습니다.
- [ ] 기존 소리 설정·앱 백그라운드 및 복귀 동작을 확인합니다. 실물 기기와 에뮬레이터 확인 범위를 구분합니다.
- [ ] APK를 실제 설치해 실행하고 기존 앱의 업데이트 설치·데이터 유지 여부를 확인합니다.

아이콘 변경에는 리소스·내보내기·설치 결과 확인을 적용하고, 선택음 수정에는 관련 회귀 검사를 적용합니다. 검증하지 못한 기기나 실패 항목은 결과 보고에 명시합니다.

## 6. 제출물과 Git 보관

1. 구현 커밋·개발 브랜치·PR, 변경 요약, 실제 적용한 원본 경로와 Figma 링크.
2. 설치 후 홈 화면·앱 목록 및 아이콘 마스크 비교 이미지, 필요 시 짧은 A303 실행·소리 영상.
3. FOLLOW-001 원인과 조치, 로컬·원격 검사 결과, BGM 반복과 Android 실행 확인 결과.
4. 새 검토용 APK를 기존 방식으로 GitHub 릴리스에 올려 직접 다운로드 링크를 제공합니다. 기존 검토본은 보존합니다.
5. 실제 현재 배포본보다 증가한 versionCode와 해당 버전명을 사용합니다. 이전 검토본은 versionCode 17, 패키지 `com.roxhistory.demo`이며 기존 서명을 유지합니다.
6. 릴리스에 버전·소스 커밋·APK SHA-256·확인 환경·남은 문제를 기록하고, 공개 다운로드 파일의 해시가 검증한 APK와 일치하는지 확인합니다.

완료 보고는 **반영한 내용 / 확인한 결과 / 남은 사항 / APK 다운로드 / 소스·PR** 순서로 간결하게 남깁니다. 새 음악·효과음이나 에셋이 추가로 결정되면 실제 파일과 버전·출처·채택 상태를 Git에 함께 보관합니다.
