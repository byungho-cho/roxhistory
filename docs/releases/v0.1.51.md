# RoxHistory 0.1.51 cloud test

## Implemented

- Fresh game begins without headquarters, with wood/stone/seeds at 99,999 and population 0/0. Existing saves are not reset.
- Build headquarters, resident huts, outposts, hearths, training grounds and shrines. All six entries are visible; locked entries show their requirements.
- HQ 1 permits1 resident hut, HQ 2 permits2, HQ 3–4 permit3. Hearth/training unlock atHQ 2; shrine/outpost atHQ 3. Other building levels cannot exceed HQ level.
- Free placement and relocation use preview, confirm/cancel, world-boundary and obstacle validation. Upgrade-in-progress buildings cannot move until finished or cancelled. HQ cannot be demolished.
- Durable construction/upgrade jobs continue offline, independently of hero actions. A progress bar, hammer and44px cancellation control are shown. Cancellation rechecks completion and refunds the exact materials paid once.
- Normal building time by target level:1minute,10minutes,30minutes,3hours. Debug10x speed changes only building clocks and preserves completed progress when switched mid-job.
- Normal mode has one builder. Unlimited builders,10x construction and red boundary display are separate explicit development switches. Reset requires confirmation. Only settings-related dialogs dismiss on their dimmed backdrop.
- Actual movement/collision region is60/70/80/90% by HQ tier relative to the frozen overview, independent of device aspect ratio and live camera zoom. Red outline displays that same polygon when enabled. Existing fog art is preserved.
- Residents arrive in random parties of1–3. Admission is all-or-nothing and requires available housing. Each hut holds1/2/3/5 by level; HQ is excluded. Upgrading capacity does not create residents.
- Up to15 admitted residents appear and can be assigned wood/stone jobs. A worker harvests one cargo, returns to the current HQ and deposits it before repeating. Moving HQ updates the return target. No HQ means cargo is retained.
- Resource count5/10/10/20 by HQ level; seeded valid placement,5–10minute regeneration, staggered fade-in and blink/fade-out depletion. Depleted objects stop blocking input/collision immediately.
- Approved L1–4 building/foundation art, resident icon, two-seed icon, menu-label overlap and three additional facility-side icons integrated. Training/shrines share a ground contact line; low buildings are centered.
- Sparse work audio is shared across durable jobs instead of continuously looping.

## Verification

Run with Godot 4.5.1:

`python3 tools/test_v0151.py --godot /path/to/Godot_v4.5.1-stable_linux.x86_64`

`python3 tools/verify_approved_assets.py`

The focused suite checks state, save migration, atomic cancellation, clock changes, input handlers, layout rectangles at multiple aspect ratios/zooms, resource and resident behavior, source-art transforms and mixer behavior. It does not render gameplay pixels and does not replace Android installation, touch, memory or performance validation. Legacy tests asserting the former synchronous construction, fixed demo costs or hidden move button are superseded, not a claimed full-suite pass.

## Test tuning and intentionally deferred work

- New visitor interval is60seconds for this test build. This is not a final balance decision.
- New layered cloud artwork and reveal cinematics are deferred. The debug movement boundary is the test target.
- The proposed gold menu connector is not included because final approval remains pending.
- Character-body remodeling is not newly generated or substituted here; resident population/jobs and HUD icon are updated.
- Shrine/hearth/training provide construction and leveling only. Combat, training simulation, religion and dungeon gameplay are not newly implemented.
